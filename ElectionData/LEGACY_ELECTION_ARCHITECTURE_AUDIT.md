# Legacy election architecture audit

The reference set was the local Ballotics 2.3.1 source, the April 2026 local 2.4 archive, the reviewed 2.3.1 restoration at `4d9f44c355b9b0047d23eb7fa33c82d5a9747c3d`, and the surviving 3.0 consolidated Swift files. In 3.0, the recovered application schema, startup coordinator, election screen, county detail screen and contingent results components were available. The recovered tree lacks the full original geospatial and election import layers. [Preserved Ballotics 2.3.1](https://github.com/mrboss302/balloticsIOS/tree/4d9f44c355b9b0047d23eb7fa33c82d5a9747c3d).

| Reference | Retained concept | 4.0 research implementation |
| --- | --- | --- |
| 2.3.1 and 2.4 `PresElection.swift`, `PresElectionStateDataLoader.swift`, `PresElectionDataProcessor.swift` | Separate candidate totals, explicit winner flags, electoral majority and state allocation rows | Normalize CSV and JSON together with source row locators, explicit types, stable person IDs and one manifest. Replace direct import from mutable `master`, presentation-coded keys and exported Documents JSON. |
| `PresElectionResultsMap.swift`, `SplitVoteKeyShape.swift`, historical map components | Dated state and territory polygons, discernible split allocations, candidate legends | Preserve the lab’s date contract and two existing renderers. Group reported allocations by geography key and apply stripes from candidate IDs. Replace year/state drawing branches and manual label offsets with result metadata and inspection. |
| `ContingentElectionHistoricalMap.swift`, 3.0 `ContingentElectionMap.swift` and `ElectionsScreen.swift` | Explain congressional decisions and identify multiple candidates from the same affiliation | Store the presidential decision and House outcome separately from electoral rows. Retain candidate distinctions within a party. Disclose the 1836 Senate decision for vice president. |
| `CountyElectionData.swift`, `PresElectionCountyDataProcessor.swift`, `ElectionCountyResultsMap.swift` and 3.0 county detail | Local candidate returns, selection, detail panel, statewide context and year-scoped caches | Load one county result package at a time. Record reported and listed votes separately. Derive margins only when both leading candidates and the denominator are validated. Replace the all-year download and delete-before-batch-save flow. |
| `MapHelpers.swift`, county map, thematic dot map | Connecticut traditional counties, Alaska House districts, regional Albers and insets | Resolve source namespaces and vintages explicitly. Keep existing Census polygons intact and generate a separate lab display file. Preserve the WGS 84 Albers lab implementation and named insets. |
| 3.0 `StartupCoordinator.swift`, `BalloticsModelContainerFactory.swift`, `BalloticsSchemaMigrationPlan.swift` | Isolate data import and storage services, account for already-installed data | Use a separate research SwiftData file, a model actor and a transaction for each activation. Leave the production schema, migration chain and model containers in their projects. |

The lab baseline was `e423d4f1e28ec70acb1d3d3099c71c7e9487a7c4`. Six local commits preserved the native renderer, temporal county filters, Albers insets, historical election geography and prior measurements. Review covered changed paths, commit patches, asset additions, credential signatures, local path disclosure and whitespace. The range contains code, project configuration, documentation and benchmark logs. The original branch tip was backed up by fast-forward and independently verified before this implementation.
