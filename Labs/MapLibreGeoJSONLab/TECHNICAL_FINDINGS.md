# MapLibre Native GeoJSON technical findings

**Recommendation — Not yet qualified.** Direct GeoJSON is technically viable for the four tested files in the iOS simulator. The lab rendered the original bytes offline and used MapLibre's rendered-feature queries for selection. The physical iPhone and iPad were unavailable. Sustained presented-frame performance and the memory envelope on target iPhones still govern the Ballotics 4.0 decision. See [benchmark results](BENCHMARK_RESULTS.md).

## Starting branch audit

The original SwiftUI app embedded MapLibre's dynamic XCFramework and compiled. It failed to launch because the executable lacked a runpath to its embedded Frameworks directory. After correcting the runpath, MapLibre 6.31.0 raised an Objective-C exception when the initial selection layer used an unconditional false `NSPredicate`. The revised layers start hidden and become visible with a supported identity comparison. The validated official binary package stays at 6.31.0. The SwiftPM lock file records the distribution revision and the package manifest checks the XCFramework checksum. [MapLibre SwiftPM distribution](https://github.com/maplibre/maplibre-gl-native-distribution/tree/13e41ab3d77ff5113e7e5d4ee87803b1f81f5683), [MapLibre iOS release](https://github.com/maplibre/maplibre-native/releases/tag/ios-v6.31.0), [BSD 2-Clause license](https://github.com/maplibre/maplibre-native/blob/ios-v6.31.0/LICENSE.md).

The initial implementation accepted an idle notification as its only load indicator, assumed every selectable feature had a string GEOID, and copied unvalidated imports into persistent Documents paths. The lab now verifies the active fill layer has a queryable polygon in a rendering callback before accepting idle. It validates imports off the main actor, retains an app-local temporary copy for the active import, rejects invalid input before replacing the map, and preserves selection during camera and paint changes. The Census top-level feature IDs repeat across each entire file. The validator checks unique GEOIDs, widths, and consistent state/component and qualified IDs. The historical file uses the unique per-record numeric `ID_NUM` and displays the date range alongside FIPS.

## What the framework does

The app supplies the original local URL to `MLNShapeSource` with default options. In the pinned core, the file source returns bytes, a background task converts those bytes to the native GeoJSON representation, and `GeoJSONData::create` builds the C++ GeoJSON-VT index. Render-source updates populate an internal tile pyramid from that index. During navigation MapLibre asks the same index for tiles at the new camera, with internal clipping, quantization and simplification. Replacing a dataset creates a new source and rebuilds that index. The laboratory validator performs an independent pass once per bundled dataset per app process to produce counts, bounds and identity metadata. [Pinned source loading](https://github.com/maplibre/maplibre-native/blob/ios-v6.31.0/src/mln/style/sources/geojson_source.cpp), [Pinned GeoJSON-VT construction](https://github.com/maplibre/maplibre-native/blob/ios-v6.31.0/src/mln/style/sources/geojson_source_impl.cpp), [Pinned render-source updates](https://github.com/maplibre/maplibre-native/blob/ios-v6.31.0/src/mln/renderer/sources/render_geojson_source.cpp).

Name and attribute inspection use `visibleFeatures(at:styleLayerIdentifiers:)` restricted to the current fill. The base source is shared with the border and selected-feature style layers. GEOID-based selection changes the highlight filter and visibility. Recoloring sets fill paint. Both operations apply within the current source revision. The renderer can still rebuild tile-layer buckets after a filter change. Rendered hits reflect the visible, tiled approximation. Tiny features and near-boundary taps may differ by zoom. A raw import with no stable identity takes a separate path on tap. After a rendered hit, it finds a containing polygon in the original file and adds that single original shape as an overlay. That tap may require a new read and scan, and overlap ordering or a simplified boundary can disagree with the original at the tap coordinate. Use unique per-feature identifiers for repeatable inspection. [MapLibre iOS feature and identity API](https://maplibre.org/maplibre-native/ios/latest/documentation/maplibre/mlnfeature/).

## Performance implications

The default-source launch series reached a queryable frame in a median of roughly 0.39 s for states, 0.58 s for districts, 0.92 s for modern counties, and 2.06 s for the historical import. These intervals start at Swift app initialization. Validation is a sizable share of the delay. For historical counties, the copy and validation alone took about 1.08 s. Reusing validation metadata on subsequent switches avoids the app-side parse, while replacing the native source still incurs source processing.

The three bundled datasets peaked at 51–351 MiB footprint during navigation. Historical counties peaked at 1,165 MiB and logged a 66.3 ms rendering callback gap. Its multiple historical vintages cover overlapping territory. It has 5.5× as many features, 3.3× as many coordinate positions, and 10.4× as many polygon parts as the modern county layer. The extra coverage and multipart workload accompany the larger native index and tile working set. These measures describe simulator process behavior.

The historical source-option sweep kept the raw input. The smaller buffer reduced sampled peak footprint from 1,217 to 749 MiB. Higher tolerance brought it to 944 MiB. A source zoom cap of 8 yielded 1,206 MiB over a route that stayed under camera zoom 6. A buffer of 32 is the leading device-test candidate. Seam fidelity, coastal detail and boundary hits need checking before adopting it. MapLibre's ambient cache applies to downloaded resources. The local GeoJSON index and renderer tile pyramid govern this test's active working set.

## Fidelity and scope

Source validation checks structure, supported geometry, closed rings, finite WGS 84 coordinates and Census ID consistency. Topology, source authority, and election applicability remain open. The national camera begins with the lower 48, with Alaska and Hawaii accessible via presets. The raw Census coordinates span the antimeridian and reach American Samoa. Historical-county vintages overlap by design. The historical layer displays the available vintages together and identifies the topmost hit with its date range. Interactive satellite territories, exhaustive small-polygon/holes and cross-tile seam validation, VoiceOver, and cartographic comparisons remain open.

The lab bundles a background-only style and loads shape data from local URLs. A URL protocol installed on MapLibre's ephemeral session rejects HTTP(S). A local file provider can still fetch an iCloud-hosted document outside that session. The historical file was staged in a local simulator folder.

## Comparison with the existing Ballotics Maps Lab

The existing Final Offline Qualification experiment generates local raster tiles for separate style/resolution combinations, reads a manifest, caches decoded tile images, and performs selection against a separate geometry layer. Its reported 16 MiB decoded LRU covers only retained cache entries. Active, fallback and in-flight images, selection geometry, and graphics allocations also contribute to total memory. That lab reported native functional checks and mathematical hit parity, with unresolved long-run memory, full 8× reference, transition frames, and device qualification. The comparison draws on that lab’s Final Offline Qualification report.

MapLibre consumes the same raw files across camera scales, builds an in-process vector tile index, renders fill/stroke, and provides feature querying and selection on the same source. That removes a user-managed tile generation, packaging and lookup step for this experiment. Its native index, tile and graphics memory remain part of the app's memory cost. A side-by-side performance ranking needs identical geometry, viewport, pass, build configuration and device. Reuse the earlier manifest, geography-vintage and offline-contract checks regardless of renderer.

## Decision gates

Strategy A established direct offline rendering in the simulator. Strategy B found a measurable historical memory reduction with original input bytes. Standalone simplification and a prebuilt vector-tile pipeline were outside the measured cases.

The next milestone is a Release run on a physical iPhone with the original Census files and historical counties. Compare default and reduced-buffer configurations for history. Record actual presented frames, hitches, memory growth over longer routes, allocation peaks, and memory after releasing the source. Pair that trace with seam, narrow-feature, coast and boundary-hit comparisons on the same geometry. Use the device results to decide whether a separately reproducible simplified asset is warranted. Evaluate offline vector tiles if raw and simplified assets fail the device requirements.
