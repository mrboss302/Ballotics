# Albers renderer baseline audit

Baseline commit `1625fef20727c512d00be2db2ca8e82311f3e4e6` matches the starting GitHub research branch. The original renderer and previous evidence are reproducible from that commit. The 0.2 app also accepts `--albers-baseline` to disable shared decoding, indexing, projected-scene and election-presentation caches, and optimized invalidation while retaining common measurement hooks. MapLibre Native 6.31.0 remains a control.

## What the original renderer does

| Stage | Original implementation | Observed limitation |
| --- | --- | --- |
| Decode and validate | Foundation `JSONSerialization` decodes a local FeatureCollection. `GeoJSON.validate` checks ring closure, coordinate bounds and identity. Historical indexing validates each record, copies active feature bytes into a temporary FeatureCollection and keeps date provenance. | In a fresh 2024 county process, validation consumed 458–470 ms for three Albers launches. Albers then opened and decoded the same data before constructing paths. |
| Project and prepare | WGS 84 ellipsoidal Albers per region. A region splits long source segments into intervals of at most one degree and wraps relative to its central meridian. A multipart feature keeps one identity across its separate projected `CGPath` parts. Even–odd fill handles exterior and interior subpaths for both drawing and picking. | The second decode, projection and path construction together consumed 418–423 ms. Later 0.2 phase timing showed that projection and path construction were the larger portion. |
| Cache and camera | The SwiftUI view holds one prepared scene for the active dataset request. `UIView` stores the center and zoom. Pinch and double tap anchor zoom under the gesture. Drawing applies a camera transform to prepared paths. | Pan and zoom reuse the active geometry. A revisited date with a new temporary URL rebuilds prepared paths. Camera fit and selection highlight scan feature parts. |
| Render and color | SwiftUI passes geometry, selection and revisions through `UIViewRepresentable`. Core Graphics draws each visible part in `UIView.draw`. Color changes rebuild only a palette indexed by scene feature. Stripes use a clipped path. | Every representable update calls `setNeedsDisplay`. Visible rectangles skip offscreen raster work only after a linear bounds scan. At low zoom, the full county bitmap must be composited on each redraw. Optional stripe work iterates across a part's bounds even where it falls outside the viewport. |
| Pick | Convert screen position through camera and inset transforms, scan parts in reverse paint order, reject outside boxes and test even–odd path membership. | A complete scan returns the topmost hit and cannot expose overlapping jurisdictions. On the baseline ARM64 host, 5,000 county probes took about 56 ms total. Picking alone was already well inside the ordinary-tap target. |
| Election changes | SwiftData loads the active package and catalog. Swift builds inspector details and styles. The current county geometry is reused for later county results. | The previous multi-second waits were outside projection and drawing for same-source updates. The 0.2 stress pilot recorded a request waiting around 5 seconds before its task entered, and another where the query section took over 6 seconds. The latter interval includes actor scheduling and awaits. Attribution within that interval remains open. |

The drawing code prepares paths on CPU and submits drawing through Core Graphics and the UIKit backing layer. In the matched simulator route the application-side draw callbacks lasted under 9 ms at 1×. The camera driver and draw callbacks advanced about once per second in the initial window and approached their nominal cadence at 8×. Time Profiler found Core Graphics display-list replay in 17,538 of 19,599 main-thread samples, inside Core Animation's commit. The most frequent leaf was `aa_render`, with 7,230 samples. This puts a substantial cost in CPU antialiasing and path rasterization downstream of the timed callback. Physical GPU execution and display deadlines remain open. The simulator rejected Instruments’ Animation Hitches template.

## Pinned MapLibre interface

The cached iOS SDK's public `MLNStyle.h` and `MLNMapView.h` expose geographic camera and coordinate conversion interfaces for the native Mercator pipeline. The Albers projection is implemented by the lab. `MLNCustomStyleLayer.h` exposes a Metal encoder, Metal resources and the existing map's projection matrix to a custom draw callback. Drawing an independently projected thematic scene through that callback would require the lab to supply its own Albers camera, insets, culling, picking and accessibility. The standard GeoJSON source keeps its real longitude and latitude. [MapLibre Native architecture](https://maplibre.org/maplibre-native/docs/book/design/archictural-problems-and-recommendations.html) · [iOS Metal custom style layer](https://maplibre.org/maplibre-native/ios/latest/documentation/maplibre-native-for-ios/customstylelayerexample/).

The optimized path keeps the same projection, path semantics and temporal validator. It shares a validated decode for bundled geometry, builds a spatial index with the prepared paths, suppresses unrelated view redraws and adds bounded, per-version reuse. See [architecture](ALBERS_RENDERING_ARCHITECTURE.md) and [benchmark results](ALBERS_PERFORMANCE_BENCHMARKS.md).
